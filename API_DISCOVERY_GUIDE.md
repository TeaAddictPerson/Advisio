# Руководство по определению параметров API

## Способы определения параметров и endpoint'ов для API

### 1. **Использование инструментов разработчика браузера (Chrome DevTools)**

#### Шаги:
1. Откройте сайт Kufar.by или Kvitki.by в браузере Chrome
2. Нажмите `F12` или `Ctrl+Shift+I` для открытия DevTools
3. Перейдите на вкладку **Network** (Сеть)
4. Обновите страницу или выполните поиск на сайте
5. Найдите запросы к API (обычно они содержат `/api/` или `api.kufar.by`)
6. Кликните на запрос и посмотрите:
   - **Headers** (Заголовки) - URL, метод, заголовки запроса
   - **Payload** (Полезная нагрузка) - параметры запроса
   - **Response** (Ответ) - структуру ответа API

#### Пример для Kufar:
- Откройте https://www.kufar.by
- Выполните поиск объявлений
- В Network найдите запросы к `api.kufar.by`
- Изучите параметры запроса (cat, rgn, size, sort, cur)

### 2. **Анализ существующих библиотек**

На GitHub есть неофициальная библиотека для Kufar API:
- https://github.com/dionchaika/kufar-api

Изучите код этой библиотеки, чтобы понять структуру запросов.

### 3. **Официальная документация**

Попробуйте найти:
- Раздел "Для разработчиков" на сайте
- API документацию в формате OpenAPI/Swagger
- Контакты технической поддержки для получения доступа к API

### 4. **Использование Postman или curl**

1. Скопируйте запрос из DevTools
2. Импортируйте в Postman или выполните через curl
3. Экспериментируйте с параметрами

### 5. **Анализ мобильных приложений**

Если есть мобильное приложение Kufar/Kvitki:
- Используйте инструменты для перехвата трафика (Charles Proxy, mitmproxy)
- Анализируйте запросы, которые отправляет приложение

## Текущие параметры, которые мы используем

### Kufar API:
- **Endpoint**: `https://api.kufar.by/search-api/v1/search/rendered-paginated`
- **Параметры**:
  - `cat` - категория (1700, 1000, 2000)
  - `rgn` - регион (1 = Минск, 0 = Вся Беларусь)
  - `size` - размер страницы (100)
  - `sort` - сортировка (lst.d)
  - `cur` - текущая позиция (0, 100, 200...)

### Kvitki API:
- **Endpoint**: `https://www.kvitki.by/api/events`
- **Параметры**:
  - `limit` - лимит записей (100)
  - `offset` - смещение (0, 100, 200...)

## Что делать, если API возвращает пустые ответы

1. **Проверьте параметры запроса** - возможно, категории изменились
2. **Проверьте заголовки** - возможно, нужны дополнительные заголовки
3. **Проверьте аутентификацию** - возможно, требуется API ключ или токен
4. **Проверьте формат ответа** - возможно, структура ответа изменилась

## Рекомендации

1. Всегда используйте официальную документацию, если она доступна
2. Соблюдайте rate limiting (ограничения частоты запросов)
3. Не злоупотребляйте API - делайте разумные паузы между запросами
4. Обрабатывайте ошибки и пустые ответы корректно
